# 文案分块规则

本文件说明如何把用户提供的普通文本整理成可排版的内容块。只有在需要处理文案结构时读取。

## 基本原则

- 用户已经确认的文案是唯一内容来源。
- 先识别“这段话在表达什么”，再决定“它应该长什么样”。
- 分块、断行和视觉强调不等于改写文案。
- 不能为了适应版式而静默删句、缩写、合并或改变顺序。

## 识别顺序

按下面的顺序建立内容清单：

1. 页面标题；
2. 开场、场景或过渡；
3. 核心定义或中心观点；
4. 例子和解释；
5. 并列的问题、价值或步骤；
6. 因果、流程或关系链；
7. 页面收束句。

如果用户用“标题：”“场景：”“正文：”“总结：”等简单标签组织文本，保留这些语义层级；如果没有标签，根据段落和语义提出判断，不要直接改变原文。

## 输出的内容清单

每个内容块至少记录：

| 字段 | 说明 |
| --- | --- |
| 位置 | 属于哪一页、哪一章节 |
| 原文 | 用户提供的完整文字 |
| 作用 | 标题、解释、例子、列表项或收束 |
| 阅读优先级 | 普通、重要、核心 |
| 模块建议 | 纯文字、重点色块、列表、四宫格或关系链 |
| 是否需确认 | 视觉转换是否可能改变原意 |

这份清单可以是内部结构，不要求用户手动填写 JSON。

## 必须确认的情况

在以下情况下暂停自动排版并向用户确认：

- 把一整段解释改成关键词；
- 把连续文字改成流程图或关系链；
- 把多个句子合并成一个结论；
- 删除看起来重复但仍有解释作用的句子；
- 改变原文的先后顺序；
- 为了留白而删减内容。

## 文案过长时的处理顺序

1. 先增加模块高度或调整模块间距；
2. 再尝试拆分段落或更换模块形式；
3. 再考虑拆页；
4. 仍然无法容纳时，明确提示溢出并询问是否修改文案。

不得把字号压缩到手机上难以阅读，也不得用不明显的方式藏掉内容。
