# 可编辑小红书知识卡片 Skill

这是一套面向小红书 3:4 知识卡片的内容分块、版式编排和 HTML/CSS 编辑方案。

它的核心目标不是“替用户重新写一遍内容”，而是把已经确认的文案和 IP 素材，整理成一张可阅读、可调整、可检查、可导出的卡片。

一句话概括：

> 保留原文的前提下，把内容拆成合适的视觉模块，再用可编辑的 HTML 画布完成排版。

## 1. 这套 Skill 解决什么问题

制作知识卡片时，真正容易反复返工的通常不是“有没有文案”，而是：

- 一段文字应该作为普通正文，还是做成重点色块；
- 多个并列信息应该做成列表、四宫格，还是保持连续阅读；
- 新增一段话后，后面的内容能不能自动往下移动；
- IP 图片能不能替换、移动和调整大小；
- 文案有没有被漏掉、裁切或压缩到手机上看不清；
- 调整完成后，能不能继续编辑并导出 PNG 或 SVG。

这套 Skill 把这些问题拆成三层：

| 层级 | 负责内容 | 结果 |
| --- | --- | --- |
| 内容层 | 按章节和语义分块，识别标题、正文、强调句和步骤关系 | 保留原文，形成可排版的内容块 |
| 版式层 | 为内容块选择普通文字、重点色块、列表、四宫格等模块 | 内容长度变化时，模块仍能顺序排列 |
| 编辑层 | 在浏览器中直接改字、增删模块、调整顺序和图片 | 用户可以继续人工微调，而不是只能重新生成 |

## 2. 已支持的主要功能

### 2.1 文案分块，不替用户改稿

输入已经确认的文案后，Skill 可以：

1. 按页面和章节拆分内容；
2. 区分标题、正文、重点句、例子、列表项和收束句；
3. 判断哪些内容更适合普通阅读，哪些内容适合视觉强调；
4. 识别适合做流程关系或并列模块的内容；
5. 将结果交给 HTML/CSS 画布排版。

默认原则是：原文优先，排版服务于表达。

### 2.2 可编辑 HTML/CSS 画布

HTML 是本项目的主要编辑载体，适合在浏览器中直接调整：

- 点击文字直接编辑；
- 增加新的内容模块；
- 删除用户后续新增的模块；
- 将模块上移或下移；
- 调整图片位置和大小；
- 修改后重新检查版式；
- 导出 PNG 或 SVG。

页面采用正常文档流排列。某个模块内容变长时，后面的模块会随之下移，不需要手动重新计算每个模块的绝对坐标。

### 2.3 可选择的模块形式

当前原型已经支持以下四种通用新增模块：

| 模块 | 适合内容 | 视觉特征 |
| --- | --- | --- |
| 纯文字 | 过渡句、补充说明、较完整的叙述 | 不加色块，保持连续阅读 |
| 重点色块 | 定义、结论、需要记住的一句话 | 青色浅底或强调边线，突出一个重点 |
| 列表 | 有顺序或有并列关系的内容 | 便于快速扫读 |
| 四宫格 | 四个相对平行的价值、特点或步骤 | 形成稳定的并列结构 |

流程、链路和关系图可以根据页面内容专门设计；目前它们还不是一个可以任意新增的通用按钮。需要通用关系链模块时，应作为下一步功能扩展，而不是假设当前按钮已经支持。

### 2.4 IP 图片编辑

IP 不由 Skill 重新设计，也不由生图模型临时生成。用户提供什么角色素材，页面就使用什么角色素材。

当前原型支持：

- 从本地文件替换 IP 图片；
- 在画布中直接拖拽图片，调整左右和上下位置；
- 调整图片大小；
- 使用滑杆精确调整垂直位置；
- 一键恢复图片的初始位置。

### 2.5 版式检查

导出前可以运行检查，重点确认：

- 必要文案是否仍然存在；
- 自定义模块是否留有空字段；
- 内容是否超出 3:4 画布；
- 正文字号是否被压缩到难以阅读；
- 中文断行是否自然；
- IP 是否被裁切或遮挡；
- 文字与图片、模块之间是否发生碰撞。

检查的作用是提示问题，不是替用户静默删字或重写内容。

## 3. 推荐的标准工作流程

```text
确认文案与页面顺序
        ↓
按章节和语义分块
        ↓
提出模块建议，并标记需要用户确认的转换
        ↓
生成 HTML/CSS 画布
        ↓
人工编辑文字、模块和 IP 位置
        ↓
运行版式检查
        ↓
导出 PNG / SVG
        ↓
缩小到手机信息流尺寸复核
```

### 第一步：准备输入

通常只需要提供已经确认的文本。可以是一页内容，也可以是多页内容；多页内容用“第 01 页”“第 02 页”这样的标题分开即可。

如果有对应的 IP 图片，也一并提供。没有额外说明时，Skill 会沿用已经确认的画布比例、字体、颜色和整体风格。

可以额外补充，但不是必填项：

- 哪些句子必须重点强调；
- 哪些内容希望做成链路、列表或色块；
- 某页希望采用的人物动作；
- 允许使用的页面模板或参考图。

### 第二步：做内容分块

先回答“这一页有哪些信息”，再回答“这些信息应该长什么样”。不要一上来就把所有文字都塞进同一种卡片。

建议至少区分：

- 页面标题；
- 开场或场景说明；
- 核心定义或观点；
- 例子和解释；
- 并列问题或价值；
- 流程关系；
- 页面收束句。

### 第三步：确定模块

Skill 可以先提出模块建议，但以下情况应让用户确认：

- 把完整段落改成流程图；
- 把多个句子压缩成关键词；
- 把连续叙述拆成四宫格；
- 需要改变原文顺序；
- 需要删除或合并有实际解释作用的句子。

### 第四步：在浏览器中调整

打开生成的卡片文件后，直接在画布中编辑即可。常用操作包括：

- 点击文字，直接修改内容；
- 选择模块形式，新增一段补充内容；
- 删除自己新增的模块；
- 将模块上移或下移；
- 替换、拖拽或调整 IP 图片；
- 检查版式，再导出 PNG 或 SVG。

画布是主要工作界面，不要求用户理解 HTML、CSS、JSON 或目录结构。只有在浏览器对本地图片加载、字体或导出存在限制时，才需要改用本地静态服务器打开文件。

编辑结果需要通过页面导出或保存修改后的 HTML 来保留。当前版本不会自动把画布中的临时编辑回写到内部数据文件。

## 4. 文本输入示例

最简单的输入方式就是直接提供正文，例如：

```text
第 03 页｜为什么需要 Skill？

场景：
比如每次做竞品分析，你都要重新交代查哪些资料、怎样核实来源、按什么结构输出。

三个麻烦：
1. 重复交代：相同的要求，每次任务都要再输入。
2. 注意力被稀释：要求越堆越长，关键步骤更容易被淹没。
3. 难以维护：想改一个步骤，还得检查它是否和旧规则冲突。

底部收束：
把相对固定的步骤、参考资料和工具使用方式整理起来，需要时再调用。
```

用户不需要手动填写 `type`、`id`、`moduleHint` 等技术字段。Skill 会先识别标题、场景、例子、并列问题和收束句，再提出适合的模块形式。

如果用户已经明确指定了某段必须做成色块、列表或链路，Skill 按指定方式执行；如果没有指定，Skill 只提出建议，不擅自改变原文的语义结构。

## 5. 文案处理规则

| 情况 | 默认处理 |
| --- | --- |
| 文案已经确认 | 原样保留，只做分块、断行和视觉层级处理 |
| 某段适合强调 | 建议使用重点色块、加粗或单独模块，但保留原文 |
| 某段适合做链路 | 提取关系并提出链路版式，重要语义变化需确认 |
| 内容过长 | 优先调整模块比例、拆分模块或换版式 |
| 内容仍然放不下 | 明确提示溢出，询问是否拆页或删减 |
| 内容存在疑似重复 | 标记出来，不能自行合并 |
| 原文存在事实或表达问题 | 提醒用户确认，不把排版 Skill 当作内容审核工具 |

最重要的一条：

> 不因为“画面放不下”就偷偷删掉、改写或压缩用户已经确认的内容。

## 6. 视觉与排版基线

当前原型采用统一的知识卡片基线：

| 项目 | 当前方案 |
| --- | --- |
| 画布 | 1080 × 1440，比例 3:4 |
| 背景 | 纯白 |
| 主文字 | 深色，用于标题和正文 |
| 强调色 | 从 IP 提取的青色，用于 Skill、重点词和结构线 |
| 标题 | 最大层级，控制数量，承担页面主叙事 |
| 正文 | 稳定字号和行距，优先保证手机阅读 |
| 强调文字 | 在标题、正文、强调三层之间控制数量，不做过多字号变化 |
| 留白 | 作为信息层级的一部分，避免每个空白处都被填满 |

当前页面的字体使用系统字体回退栈。不同电脑未安装相同字体时，字宽和换行可能变化，因此正式发布前要在实际使用的电脑上复核。

## 7. IP 素材要求与边界

### 推荐格式

- `PNG`：最推荐，尤其是透明背景 PNG；
- `JPG`：适合不需要透明背景的图片；
- `WebP`：浏览器支持较好，但跨工具导入前建议先确认兼容性。

图片最好提供足够大的原图，并避免已经被强裁切或压缩到模糊。若人物需要和文字形成互动，优先提供对应动作的独立素材。

### 不做什么

- 不重新设计用户的脸型、五官、发型和服饰；
- 不用无关图库人物替代用户 IP；
- 不在缺少可靠素材时擅自生成另一个角色；
- 不把人物压到文字上来弥补版面空洞；
- 不保证仅靠 CSS 就能修改图片内部的五官、线稿或服装细节。

如果素材不足，正确做法是保留原图、调整版式，或者请用户提供新的 IP 图片。

## 8. 模块和编辑权限

页面模块分为两类：

| 类型 | 作用 | 是否允许删除 |
| --- | --- | --- |
| 固定模块 | 页面原始结构，例如标题、场景、问题和收束 | 默认不允许删除，避免误删原文 |
| 用户新增模块 | 用户临时添加的补充说明或新内容 | 可以删除、上移、下移 |

这种限制是为了同时保留两点：

1. 用户可以灵活增加内容；
2. 已确认的原始内容不会因为误操作消失。

如果需要删除固定模块，建议先明确修改页面内容，再由维护者更新原始结构，而不是绕过保护直接删除。

## 9. 导出格式与兼容性

| 格式 | 适合用途 | 可编辑性和注意事项 |
| --- | --- | --- |
| HTML/CSS | 主要编辑、反复调整 | 保留文字、模块和交互，是最完整的编辑源 |
| PNG | 发布到小红书、发送预览 | 视觉最稳定，但导出后不可继续编辑文字 |
| SVG | 交换、归档、尝试导入 Figma | 当前导出包含 HTML/CSS 渲染内容，复杂样式和 `foreignObject` 在不同软件中可能变化 |
| Figma | 后续人工设计微调 | 可作为辅助工具，但不保证 HTML 导入后所有文字和样式都变成原生可编辑图层 |

因此，本项目的实际优先级是：

```text
HTML/CSS 作为编辑源
→ 浏览器检查和微调
→ PNG 作为发布文件
→ SVG 作为交换文件
→ Figma 作为可选的后续人工调整工具
```

不要把“成功导出 SVG”理解成“已经保证 Figma 内全部文字可编辑”。这需要在目标版本的 Figma 中实际导入并逐项检查。

## 10. 明确使用边界

这套 Skill 可以帮助你完成：

- 将已确认文案分成清晰的章节和模块；
- 建议普通文字、重点色块、列表、四宫格等表达形式；
- 生成统一的 3:4 HTML/CSS 卡片；
- 让新增内容进入正常文档流，推动后续模块下移；
- 继续手动调整文字、模块和 IP 位置；
- 做基本的内容完整性和溢出检查；
- 导出 PNG 和 SVG。

它不能保证：

- 任意长度文案都一次排版完美；
- 自动理解所有文案的真实语义和重点；
- 不经过确认就替用户删减、改写或重组内容；
- 不同电脑、浏览器和字体环境下像素级一致；
- SVG 导入 Figma 后一定保留原生文字图层；
- 自动替用户完成内容事实核验；
- 自动生成符合用户 IP 的新动作，而不改变角色特征；
- 自动把浏览器里的临时编辑永久保存回源文件；
- 代替用户做最终发布前的视觉判断。

## 11. 发布前检查清单

### 内容

- [ ] 页面标题和页码正确；
- [ ] 原文没有漏字、错字或被静默改写；
- [ ] 重点句、例子和解释都仍然存在；
- [ ] 模块顺序符合阅读逻辑。

### 视觉

- [ ] 画布比例为 3:4；
- [ ] 标题、正文和强调层级清楚；
- [ ] 文字没有贴边，留白足够；
- [ ] IP 没有被裁切，也没有遮住文字；
- [ ] 青色使用集中，没有让每个字都变成重点。

### 技术

- [ ] 运行版式检查，没有溢出提示；
- [ ] 自定义模块没有空内容；
- [ ] 在手机信息流缩略图尺寸下，标题和核心定义仍然可读；
- [ ] PNG 已打开检查；
- [ ] 如果使用 SVG 或 Figma，已经实际验证导入结果；
- [ ] 重要修改已保存为可恢复的 HTML 源文件。

## 13. 后续适合扩展的方向

以下功能有明确价值，但不应在没有验证需求前一次性做得过重：

1. 通用的流程链路模块；
2. 图片裁切、旋转和更精细的定位；
3. 浏览器内的撤销、重做和自动保存；
4. 一套可切换的字体与字号预设；
5. 多页项目管理和批量导出；
6. 更稳定的 SVG 原生文本导出；
7. 不依赖插件的 Figma 交换流程验证。

扩展时仍然遵循一个原则：先保证“内容不丢、模块可控、结果可检查”，再增加自动化和装饰能力。
